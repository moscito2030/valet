# Valet｜橋牌賽事記分與管理

**從賽前編排、現場收分，到成績查詢與賽後檢討，在同一個網站完成。**

Valet 是繁體中文的橋牌賽事工具，適合橋藝社、俱樂部與小型賽事主辦方。支援隊制賽、雙人賽與 迷你橋牌，裁判可以管理賽程和成績，賽員與觀眾則能用手機查看對戰、排名與逐副牌局。

雙人賽還可以讓搭檔掃描 QR Code，在自己的手機上輸入成績，由對手核對確認，再由裁判結算發布。從桌邊到成績表，減少紙本傳遞、重複抄寫與人工換算。

## 使用手冊

網站的「使用手冊」入口位於側欄，網址為 `/manual/`。[閱讀手冊原稿](manual/src/index.md)。手冊涵蓋賽前編排、裁判與賽員收分、計分、匯入匯出及部署維護。

本機使用 `npm run manual:build` 產生網頁、`npm run manual:check` 檢查連結；啟動開發伺服器與正式建置會自動產生。首次建置會下載固定版本並校驗 SHA-256 的官方 mdBook，不需安裝 Rust。

## 把辦賽時最花時間的工作接起來

| 辦賽時的問題 | Valet 能做的事 |
| --- | --- |
| 名單、賽程、牌型與成績分散在不同檔案 | 集中管理賽事與賽段，各賽段保有自己的名單、計分法與成績 |
| 收分後還要手算 IMP、VP 或重新整理排名 | 輸入合約與實得墩數，自動換算原始分、比較分與排名；更正後重新計算 |
| 不知道哪桌還沒交分、哪桌尚未核對 | 查看本圈收分進度與落後桌次；俱樂部收分另有對手確認流程 |
| 賽員一直詢問排名、對手與自己的成績 | 分享網站連結，讓大家自行查詢桌次、對戰、總排名與個別成績 |
| 想回顧一副牌，卻得另外找牌譜與分析工具 | 在逐副成績旁直接看四家牌型、雙夢家分析與互動試打 |
| 更正後說不清楚改了什麼 | 保留操作時間、原因及成績前後差異，方便追查與核對 |

## 賽前：準備名單、賽程與牌局

先建立保存名稱、前綴與共用地點的賽事，再新增賽段。賽事可先不安排任何賽段；賽段預設沿用共用地點，也能另設。新增賽段時，圈數可留空，先建立參賽名單。裁判之後在「匯入／匯出 → 指定賽程編排」設定圈數與每圈牌數、選擇賽程編排，預覽並確認後產生賽程。未設定前會顯示「待設定賽程」，不能開始收分或結束賽事；已有成績後不可重建編排。隊制賽可選循環對戰，雙人賽可選適用的 Mitchell、Howell 或全場同牌輪轉。

- **賽事與賽段管理**：一場賽事可設多個賽段，分別安排隊制或雙人賽、名單、牌數與計分方式。
- **直接選擇賽程編排**：依桌數與圈數提供適用的 Mitchell、完整 Howell、3/4 Howell 或全場同牌輪轉；預覽各圈桌次、方向與牌號後再套用。
- **雙冠軍賽制**：3–40 桌可選 Double Winner Mitchell，分別輸入 NS／EW 搭檔名單，各組獨立排名，支援 迷你橋牌 與 CrossIMP。奇數桌最多打桌數圈；偶數桌可用 Skip Mitchell（最多桌數減一圈），或共牌／中繼版本（最多桌數圈）。
- **知道要準備多少牌**：顯示牌組數、輪空與共牌需求，並計算不共牌時所需的完整牌套數。
- **匯入既有資料**：支援賽程編排 CSV、牌型 PBN，以及各圈時間區間 CSV；可先驗證與預覽。
- **產生隨機牌局**：在裁判後台產生 PBN，下載或套用到尚未收分的賽段。也可用 Deal Source 指定點力、牌型、花色長度或特定手牌，準備練習題。
- **迷你橋牌 模式**：提供五種花色／無王搭配「一線、成局」的十種合約，採無身價計分，適合入門活動。

## 比賽中：讓收分、核對與排名連在一起

裁判或賽務可在後台選擇桌次與牌號，輸入合約、莊家、加倍與實得墩數，立即查看原始分。也能批次匯入成績 CSV，減少逐筆輸入。

| 比賽形式 | 計分與查看方式 |
| --- | --- |
| 隊制賽 | 開閉兩室比較、IMP 與 WBF 連續 20–0 VP；對戰收齊後換算 VP |
| 雙人賽 | MP、CrossIMP 或 ButlerIMP；兩種 IMP 計分可設定去頭去尾 |
| 迷你橋牌 | 自動處理一線與成局門檻、超墩及宕墩，不需輸入線位與身價 |

**雙人賽俱樂部收分**讓每對搭檔使用專屬 QR Code 或連結：

1. 裁判指定當圈與輸入方。
2. 輸入方在手機提交本桌成績，另一方核對確認。
3. 確認後鎖定該桌成績，避免再次改動。
4. 裁判查看全圈進度，結算後對外發布成績。

另提供 **大賽收分模式**：雙人賽與隊制賽的裝置固定在桌次，一般隊制賽依桌號與開閉室分開簽發。換圈自動載入對戰，同機交給對方核對後鎖定，裁判結算後公開。設定與操作見[使用手冊](manual/src/director.md)。

需要處理例外時，可取消牌局、調整參賽者扣分，或對隊制賽設定不平衡合約，分別計算雙方的 IMP 與 VP。更正與判罰均留下操作紀錄；遇到同時更新，版本檢查會阻止舊資料直接覆蓋新資料。

## 賽員與觀眾：用手機找到自己關心的成績

- **總排名**：查看名次、得分與完成牌數，也能搜尋、追蹤參賽者。
- **圈次與對戰**：查詢各圈桌號、對手與牌號；雙人賽另顯示該圈開始前的累積成績。
- **隊伍／搭檔成績**：集中查看自己的逐副結果；隊制賽可切換圈次，查看雙方 IMP 與 VP 比數。
- **個人／搭檔 Butler 統計**：依實際上場名單彙整有效牌數、每牌 IMP、正負 IMP 商數、MP 與全場排名；進行中只納入整圈已完成的成績，可按隊伍篩選。
- **逐副比較**：比較各桌合約、實得墩數與得分，從同一副牌理解分數差異。
- **進度資訊**：進行中顯示本圈收分；結束後顯示有效成績與全部已收成績筆數。

一般成績頁每 30 秒自動更新，也可手動刷新。俱樂部收分模式則依裁判結算進度公開結果。

## 賽後：成績就是檢討的入口

公開牌型後，可以直接在逐副頁面查看四家手牌、HCP、Par Contract、LoTT 與雙夢家最佳墩數，並用出牌鍵盤試打、回退，觀察不同出牌的結果。

點擊一家姓名即可切換該家視角：首攻前只看自己的手牌，首攻後加上夢家手牌與本墩出牌。也能下載單副 PBN，或輸出至 Valet Review 繼續研究。

裁判可按牌組控制公開時間。成績、賽程、各圈時間及牌型都能匯出，另有賽事 JSON 匯出，方便留存與後續整理。

## 一場比賽怎麼開始？

1. **建立賽事與賽段**：先填賽事共用資訊，再新增賽段並填日期、名單與計分方式。刪除最後一個賽段仍會保留空賽事。
2. **準備賽程**：選擇或匯入賽程編排，核對桌次、牌號與所需牌套數。
3. **準備牌局**：匯入 PBN，或產生隨機牌局；設定牌型公開時機。
4. **開始收分**：使用後台、CSV，或啟用雙人賽手機收分。
5. **核對與發布**：查看缺分、處理更正與判罰，收齊後結束賽事。
6. **分享與檢討**：分享成績頁，公開適當牌型，下載資料保存。

## 本機試用

專案名稱與 Git repository 名稱皆為 `valet`，標準 checkout 目錄為 `valet/`。目前產品範圍以本 README、現行操作文件與程式碼為準；`docs/archive/` 保留更名前的歷史規劃，不作為開發待辦。

需要 Node.js 22 或較新的相容版本。在專案目錄執行：

```sh
npm ci
npm run dev:local
```

開啟 [http://127.0.0.1:3000](http://127.0.0.1:3000)，可使用內建模擬賽事熟悉操作。

| 本機角色 | 預設測試密碼 |
| --- | --- |
| 裁判 | `local-bridge-director-2026` |
| 賽務 | `local-bridge-admin-2026` |

以上為本機測試預設值；若已設定同名環境變數，則使用自行設定的密碼。本機資料保存在 `.data/events.json`。要讓其他人的手機連線，請部署到可存取的網站；`127.0.0.1` 只供本機使用。

## 自行部署與延伸

Valet 使用 Next.js、React 與 TypeScript，可部署至 Vercel，搭配 Neon PostgreSQL 保存賽事資料。

- [部署與備份](docs/deployment.md)
- [賽事與賽段](docs/competitions.md)
- [雙人賽手機收分流程](docs/club-mode.md)
- [賽程編排與 Deal Source 支援範圍](docs/movement-and-dealer.md)

雙人賽每個賽段最多 38 對、19 圈；隊制賽最多 32 隊、31 圈，兩者每圈最多 16 副，賽段總牌數依編排計算，不另設固定上限。雙人賽預設合併排名；Double Winner Mitchell 固定 NS／EW 方向、各組獨立排名，同牌仍依各桌原始分計算比較分。各賽段分別計分，不跨段累積。Swiss 自動配對、跨組 Neuberg 調整及離線送分尚未提供。Deal Source 支援常用發牌條件，未涵蓋完整 Dealer 語言，不支援的語法會明確提示。

開發檢查：

```sh
npm test
npm run typecheck
npm run build
```

雙夢家分析使用 [bridge-dds](https://github.com/bookchris/bridge-dds-js)；VP 換算依據 [WBF 連續 VP 公式](https://www.worldbridge.org/wp-content/uploads/2019/06/VP-Scale-Functiondetails.pdf)。

## 共用牌局檢視器

本專案使用獨立 Valet Viewer 倉庫維護的 `@valet/deal-viewer`，透過 vendor/ 內固定版本打包檔安裝。沒有指向其他倉庫的本機連結，因此可獨立 npm ci、建置與部署。

修改檢視器請到 Valet Viewer，升版並執行 `npm run sync -- ../valet ../valet-review`。此指令假設三個 checkout 為相鄰目錄，且主程式目錄已命名為 `valet`；若本機尚未搬移，請傳入實際 checkout 路徑。三個專案都需驗證並各自 commit，未經使用者指定不 push。

「輸出至 Valet Review」會透過分享連結傳入目前單副牌型（不含各桌成績）。正式部署請在建置前設定 `NEXT_PUBLIC_VALET_REVIEW_URL` 為 Review 網址；本機 localhost／127.0.0.1 預設使用同主機的 3001 埠。

## 程式結構

- components/scoreboard.tsx：公開頁面的導覽與跨分頁選擇狀態；各成績畫面位於 components/scoreboard/，資料輪詢與私下檢視由獨立 hooks 管理。
- components/admin-panel.tsx：裁判／賽務後台的載入與提交協調；各功能面板位於 components/admin/。
- components/event-dialogs.tsx：建立賽事與對話框。
- components/scoreboard-shared.tsx、scoreboard-widgets.tsx：顯示格式、共用元件與瀏覽器操作。
- app/globals.css：依既有 cascade 順序載入 app/styles/ 的基礎、成績、牌局、後台、收分與賽事樣式。不要自動排序這些 import；功能樣式優先在對應檔案維護，跨功能覆寫仍須檢查桌面與手機。
- lib/events.ts：既有呼叫端的相容入口；建立賽段與示範資料位於 lib/domain/。
- lib/mutations/apply.ts：共同的版本檢查、工作副本、稽核與投影更新；dispatch.ts 按操作種類分派至計分、收分、編排、設定與牌型處理器，名單操作沿用 roster-mutations.ts。
- lib/scoring.ts：純計分函式；舊 average 統一視為取消。
- lib/store.ts：伺服器儲存模式選擇；lib/storage/repository.ts 定義原子操作介面，local.ts、neon.ts、demo.ts 分別實作。相容資料讀取集中於 hydrate-event.ts。
- tests/repository-contract.test.ts：以同一套契約驗證本機儲存與 SQL 儲存；SQL 使用測試專用 PGlite PostgreSQL 執行實際參數化查詢，不連正式資料庫。
- lib/read-models/：公開快照與裁判單副私下檢視；前者只在所有成績可見時重用儲存投影，後者只計算所選牌號。公開／私下快照不能互相覆寫。
- tests/architecture.test.ts：限制核心模組不得依賴 UI、框架或儲存實作，並檢查本地模組的執行期循環依賴。
- `npm run profile:events`：產生合成賽事，量測計分、操作、公開／私下快照與 JSON 序列化；不存檔、不連資料庫。輸出是本機 CPU 的三次暖機後中位數，不代表正式站端到端延遲。
- lib/mutation-permissions.ts、session-token.ts：角色規則與可撤銷登入憑證。
- lib/csv-cell.ts：CSV 公式防護與往返還原。
- Valet Viewer 固定版本套件：共用牌局檢視器；介面變更需在 Viewer 專案維護並更新兩個使用端。
